# dsh-moongate v0.7.2

Stops self-learning from graduating signatures that are too coarse to be safe.

## Signature width gate

Self-learning (and automatic graduation) could graduate signatures like `bash|danger-full-access|~/*` — one rule for the whole home directory. Because allow rules are matched **before** the hard-risk categories (credentials, deletion, system paths), such a rule silently bypasses the human gate for an entire directory tree.

- New `signatureTooBroad()` check rejects any signature whose directory part is shallower than two levels (`~/*`, `/*`) or sits in a sensitive root: `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.config`, `~/.dsh`, `~/.password-store`, `~/.local/share/keyrings`, `~/Library/Keychains`, `/etc`, `/usr`, `/bin`, `/sbin`, `/Library`, `/System`, `/private/etc`.
- Applied to both paths: `recordSelfObservation()` (Flash SAFE graduation) and `recordSignatureApproval()` (human-confirmed graduation).
- Rejections are audited as `SELFLEARN-SKIP` / `GRADUATE-SKIP ... 签名不可学习`, so you can see what was skipped and why.
- Two-level-or-deeper signatures behave exactly as before (`<workspace>/project/*.txt` still graduates).

## Data note

Existing rules are **not** deleted by this change. If you already have a broad self-learned rule, disable it in **审批 → 设置 → 规则库**; the gate only prevents new ones. In the author's own 7-day run, `~/*` had 0 subsequent hits and `~/.dsh/profiles/*` had 1 — both had been disabled before this release.

The regression test (`scripts/smoke.mjs`) asserts that `~/xxx.txt` does not graduate after three SAFE verdicts while the two-level case still does.

## Upgrade

Update the plugin and **restart dsh web** — the check lives in the host module, so it only takes effect after a restart. No configuration change is required.
